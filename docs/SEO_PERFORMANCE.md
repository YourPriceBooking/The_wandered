# Етап 7: ресурси й кешування

База: main `6f5ca9a` (PR #281). Next.js 14.2.28, production build.

## Що виміряно

`performance/before.json` — збірка базового main; `performance/after.json` — збірка
зміни цього PR. Однакові локальні API-фікстури: сім карток із різними URL фото,
стаття з hero/body image і чотирма рекомендаціями. Сторінки: `/`, `/usa`,
`/usa/fixture-known`, `/travel-resources`. Фікстури прибирають вплив мінливого API.

Інструмент читає початковий HTML, завантажує його CSS/JS та рахує байти. **Не
виконує JavaScript, не гідратує сторінку, не завантажує фото/сторонні iframe,
не вимірює LCP/INP/CLS або TTFB.** Gzip обчислений для кожного файла, це не
фактичний обсяг трафіку браузера. Посилання на fonts у CSS не означають, що
браузер завантажував кожен із них. Кількість preload — число HTML-елементів,
не число унікальних мережевих запитів.

| Початкові ресурси | До | Після |
| --- | ---: | ---: |
| CSS списку `/` і `/usa`, байти | 75 907 | 52 591 |
| CSS Travel Resources, байти | 76 889 | 53 573 |
| JS списку, байти | 636 477 | 614 497 |
| JS списку, обчислений gzip | 207 973 | 201 678 |
| Пріоритетні фото серед 7 карток | 7 | 1 |
| Відкладені фото серед 7 карток | 0 | 6 |
| Reddit Sans SemiBold + Jersey 10, файли | 378 348 | 78 732 |

Остаточні значення для всіх чотирьох сторінок — у JSON. Quill CSS збережений
у статтях: там великий виграш CSS не очікується. Невелика зміна gzip може
залежати від меж CSS-чанків і не означає погіршення відображення.

Відтворення з установленими залежностями:

```sh
npm run build
npm run seo:measure-performance -- /tmp/wandered-performance.json
npm run test:performance-cache
npm run test:server-articles:http
```

Звіт містить базовий HEAD; after-збірка зроблена зі зміненої робочої гілки.
Для порівняння іншої бази потрібен її окремий checkout/build із тими самими
фікстурами та вимірювачем. Не порівнювати ці байти зі скриншотами Lighthouse.

## Рішення

- Лише перша картка списку має priority; решта, рекомендації та нижній Booking
  банер — lazy. Hero статті зберігає priority, отримує responsive sizes і стандартну
  якість Next замість quality=90. Sizes карток відповідають одноколонковому
  списку 800/758 px, а не старим 33vw/50vw; рекомендації мають власні 490/400/330 px.
  Hero sizes — консервативна оцінка наявних CSS-відступів, не виміряний LCP-кандидат.
- Редакторські body images — lazy/async, iframe — lazy з доступною назвою
  uk/pl/en за відсутності редакторської. Наявні dimensions/підписи збережені.
  В API зображень немає гарантованих width/height; невідомі пропорції не вигадані.
- Повний Quill CSS перенесено з root у PostBlock: форматування редакторських
  списків/відступів/цитат збережене у статтях, не завантажується на списках/tools.
- Reddit Sans і Jersey 10 конвертовано без підмножин у WOFF2. Cmap і горизонтальні
  метрики звірені з вихідними TTF: 723 та 332 символи відповідно. `font-display:
  swap` збережено. Sen не використовується жодним видимим селектором: прибрано
  лише зайву декларацію; не підставлено інший шрифт. next/font/local оцінено,
  але глобальний preload футерного шрифту тут не потрібний; залишено CSS font-face.
  Оригінали TTF лишаються джерелом конвертації (FontTools + Brotli, flavor=woff2).
- Прибрано mount PageTransition (700 ms exit/enter) і Lenis із root. Навігація
  більше не чекає цих анімацій, сторінку прокручує браузер; немає постійного
  Lenis requestAnimationFrame. Старі невикористані модулі/пакети не завантажуються
  цим layout. ScrollToTop і механізм shy-header залишені; їхня взаємодія потребує
  перевірки на пристроях.
- GetDataClient отримує глобальних авторів/лічильники один раз на mount root,
  а не повторно на кожному pathname. Перезавантаження сторінки оновлює дані.
- Root `headers()` залишено: початковий lang uk/pl/en важливіший за штучне
  примушення всіх сторінок до static rendering. HTML/RSC та різні мови не
  складаються в загальний кеш.

## Контракт кешу й помилок

| Дані | Політика | Оновлення / збій |
| --- | --- | --- |
| Картки восьми списків | Node process-local LRU, TTL 30 s після успішного lookup, до 64 ключів і 4 MiB JSON | Після expiry наступний запит чекає свіжу перевірену відповідь; stale не віддається |
| Однакові одночасні list lookup | Одна in-flight promise на country/page | Завершення, включно з reject, прибирає promise |
| Стаття / metadata | no-store + request-local React cache | Missing — 404; збій — 500; не зберігати помилки чи видалену статтю як успішний запис |
| Рекомендації | no-store, request-local, timeout 3 s | При збої пропустити необов’язковий блок |
| Sitemap / журнал | Чинні disk snapshots з етапу 4 | Операційні правила в SEO_ARCHIVE_OPERATIONS.md |
| Автори / лічильники на клієнті | Один lookup на mount root | Нове завантаження сторінки отримує актуальні дані |

Кеш списків містить лише нормалізовані поля карток, не повні markup статей.
Перевіряються total, кількість записів і обов’язкові поля. Transport — native fetch,
`no-store`, 10 s timeout. Невалідний payload, HTTP error, timeout і network error
не потрапляють у кеш і не перетворюються на порожній список/404. Валідний total=0
є порожнім розділом. Різні країни/сторінки мають різні ключі.

30 s — термін утримання **на сервері**, не обіцянка миттєвого оновлення вже
відкритої вкладки або Next Router Cache. Після редагування стаття отримується
свіжою; картка/total може відображати попередній стан до expiry. При PM2 cluster
кожен процес має незалежний кеш; restart очищує його. Без узгодженого захищеного
webhook із backend не додано endpoint, який нібито миттєво очищує всі процеси.
Якщо потрібна негайна публікація карток — окремо узгодити Redis/event invalidation.

Живий transport smoke під час аналізу: Axios — HTTP 502 (~4.5 s), native fetch —
успіх, total=56, 7 записів (~5.3 s). Це два одиничні спостереження в цьому
середовищі, не доказ постійної помилки Axios/сервера і не порівняльний бенчмарк.
Вони обґрунтовують повторну live-перевірку та узгоджений transport із SSR статей.

Жива перевірка локальної production-збірки зі справжнім API збережена у
`performance/live-smoke.json`: головна — 200, 7 карток, 1 H1; повторний запит —
200; стаття про regenerative farm — 200, 1 H1, правильний canonical, 4 related links.
Перший запит головної зайняв 8 973 ms, повторний 89 ms, стаття 878 ms. Це одна
послідовність без браузера: підтвердження роботи SSR і короткого кешу, не
гарантія часу/uptime. Холодний upstream list запит досі повільний; кеш не усуває
потреби оптимізувати backend/мережу й перевірити production TTFB.

Перевірки PR: production build, повний TypeScript, 55 модульних і 53 production
HTTP-тести — 108 разом, усі пройдено. HTTP без JS захищає preload/lazy policy,
мови fallback title для iframe, зміст і статуси; це не тест поведінки на пристрої.

## Приймання і залишок

- CI: тести кешу (TTL/ключі/LRU/байти/coalescing/errors/recovery), HTTP-контракт
  зображень і доступних font assets; відсутність Quill CSS на списках/tools;
  збереження Quill CSS у статті, metadata/мов/статусів/архіву з попередніх етапів.
- Після деплою: мобільні/desktop переходи, Back/Forward, позиція прокрутки,
  shy-header, ScrollToTop, відкриття/керування 4 tools; перевірити вигляд шрифтів
  і форматування реальних довгих статей. Browser у середовищі не запускається
  через заборону Unix sockets, тому це не оголошується виконаним.
- Зняти однакові mobile/desktop Lighthouse або WebPageTest до/після на реальному
  сервері. Перевірити вибраний браузером hero/card srcset і LCP-кандидат.
- Search Console / CrUX: польові p75 LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1; даних
  наразі немає, досягнення не заявляється. GA залишено без неперевіреного
  перенесення/видалення; вплив сторонніх скриптів оцінюється в браузері.
- Для повного усунення image CLS потрібні реальні dimensions усіх зображень
  редактора з backend або окрема перевірена інвентаризація, не фіктивний 16:9.
- Наступний кодовий PR — етап 8: production crawl/перевірки релізу й моніторинг.
  Польові показники, пристрої та backend contracts залишаються явним прийманням.
