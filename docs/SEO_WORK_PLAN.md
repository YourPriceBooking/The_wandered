Оновлено: 17.10.2026. План збережено в репозиторії як постійний перелік робіт.
Правила: окремий PR на етап; production build і перевірки результату до публікації;
статус «виконано в main» означає merged код. Позначки поточного PR означають
реалізацію в його гілці; production/Google перевіряються окремо.

Уточнення після аналізу main `f7b6ce1`:
1. API журналу не є звичайним page/limit endpoint: повертає чотири мовні
   колекції, до 4×limit записів, без total. Запит за межами колекції може повернути
   її всю. Adapter запитує page=1/limit=100000, перевіряє унікальність ID та
   насичення ліміту, зберігає повну відповідь і сам визначає межі сторінок.
   Реально отримано 23 532 унікальні записи; для англомовного журналу — 5 892
   англійські записи, 590 сторінок (10/10/…/2). Формальний total/cursor endpoint
   бекенду лишається бажаним покращенням етапу 7; поточний контракт перевірений
   на живій відповіді, але не є новим backend API.
2. Замість автоматичного infinite scroll залишено звичайні серверні сторінки:
   початковий HTML, canonical та URL завжди описують одну й ту саму порцію.
   Native anchors дають браузеру керувати історією та відновленням позиції.
   Поведінку в інтерактивному браузері тут не підтверджено: середовище блокує
   запуск Chromium. HTTP/reload/межі/посилання перевірено автоматично.
3. Landing журналу показує три найновіші англійські записи; його page>1
   перенаправляється на відповідну сторінку new-episodes, без другого архіву.
4. Sitemap refresh: 3 паралельні колекції, 4 lookup, загальний бюджет 60 секунд
   плюс завершення поточних обмежених запитів; TTL 1 година, backoff 1 хвилина.
   Seed має totals home=56, ukraine=39, poland=24, usa=11, canada=8,
   australia=0, singapore=0, uncharted-planet=4; included=142, excluded=0.
   Lookup перевіряє існування/ідентичність і відповідність маршруту; це не
   окремий HTTP-обхід кожного production URL на серверні редиректи/noindex.
   Повний production crawl залишається приймальною перевіркою етапу 8.
5. Snapshot поза .next переживає rebuild; при заміні всього checkout варто
   задати SEO_CACHE_DIRECTORY на сталий каталог, доступний процесу Node.
   Перший холодний запит журналу потребує завантаження повної відповіді API;
   далі використовується кеш. Його оптимізація — разом із backend endpoint в етапі 7.

Перевірки цього PR: production build, повний TypeScript, 73 тести

Окремо перевірено local production із реальним журналом: 10/10/2 записи,

## Критерій завершення програми

Усі типи статей читаються без JS; 404/5xx коректні; кожен публічний шаблон має
OG/Twitter із доступним зображенням; canonical, мови, архів, schema та sitemap
узгоджені; чотири travel tools працюють; CI захищає реалізацію від регресій.
Search Console й production-продуктивність приймаються за фактичними даними,
без обіцянки конкретних позицій у пошуку.
